Fixes #196350

## What Problem This Solves

`openclaw doctor` prints two contradictory "Gateway service installation" boxes and returns early when installation drift is locked in place by an operator-owned systemd ExecStart drop-in, never surfacing the existing drop-in diagnostic. Linux systemd users with a split install get a circular "controlled by another owner → run `gateway status --deep` → run doctor" loop instead of the actionable guidance (`systemctl --user cat …`, update or remove the drop-in, rerun doctor).

## What Changed

- When the installation-repair authority check refuses because a launcher override (the operator's own systemd drop-in) locks the drift, doctor now reports the drop-in guidance instead of the "controlled by another owner" refusal. The refusal note is kept for all other failures, and no service writes are attempted on this path.
- The drop-in guidance is selected only for the specific launcher-ownership refusal: `assertGatewayServiceInstallationRepairAllowed` now throws a dedicated `GatewayServiceInstallationOwnershipError` for that case, and the doctor catch shows the drop-in guidance only for that error. Inspection failures (unavailable inspection) and service-definition changes keep their own error note, so their recovery instructions are no longer masked by the drop-in guidance.
- The guidance is emitted through a shared helper, `noteOperatorOwnedSystemdDropIn`, in `src/commands/doctor-gateway-installation.ts`, which also replaces the previously duplicated inline note — one owner for the drop-in guidance text.
- New regression tests in `src/commands/doctor-gateway-services.test.ts`: "reports the operator-owned drop-in instead of the ownership refusal when drift is locked by a drop-in", plus a parameterized test that an inspection failure and a definition change each preserve their own error instead of the drop-in guidance. Both drive the real `maybeRepairGatewayServiceConfig` with real service-layout drift computed across two temp installs, and assert no service write happens.
- Added `config/test-lines-allocations/196350-doctor-dropin-drift.txt` (+116, the exact net test-line growth of this change). On current main the test-lines ratchet has almost no headroom left, so the new regression tests need the allocation the checker prescribes.
- Rebased onto current main (`8a91b8a`); the rebase was conflict-free and the three originally changed files are byte-identical to the previously pushed versions.
