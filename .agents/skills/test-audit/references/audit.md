# Audit workflow

Use after the [authoring gate](../SKILL.md#authoring-gate); whole-subsystem
campaigns also require [CAMPAIGN.md](../CAMPAIGN.md).

## Junk patterns

Reject new tests matching these unless the [retention bar](#retention-bar)
identifies an independent contract. Audit existing matches:

- Assertion-free probes, self-comparisons, identity copiers, or expected values
  generated by the subject under test.
- Copied inventories/manifests/export lists; exact source/import/string greps.
- Private predicate/call-shape tests duplicating boundary proof; repeated
  invocations or provider-local replays of shared helpers.
- Test-only exports/globals/wrappers and production paths called only by tests.
- Mocks implementing the asserted behavior or pretending distinct APIs match.
- Fixtures supplying receipts, admission, or callback ordering the owner should
  produce; persistence asserted against a store the path never writes.
- Capability flags asserted instead of promised delivery/acknowledgement.
- Negative controls passing on an unrelated guard or unreachable rejection.
- Names promising behavior the inputs/assertions never exercise.

## Retention bar

Keep independent public API, SDK, protocol, config, migration, storage, security,
platform, default, prompt-byte, generated cross-language, package, release, and
architecture contracts. Keep observable ordering and credible regressions.
Source inspection is valid when it is the cheapest independent guard of a
user-facing key, byte, or path and survives identifier-only refactoring.
Static or slow is not a deletion reason. A baseline failure may be a product
bug: reproduce and repair its owner, not delete the test.

## Candidate evidence

Before editing, read the full test, production owner, entry point, callers,
callees, siblings, overlapping proof, CI routing, and history; inspect dependency
source/types for dependency-backed claims. Read root/scoped instructions.
Record each candidate's:

- Exact name/location and failure it can detect.
- Non-test callers of the covered production/support seam.
- Stronger remaining owner proof, or why none is needed.
- History/reason it exists and deletion it unlocks.
- Risk and focused validation command.

Missing evidence means no deletion. Keep discovery read-only and report it
before edits; prefer a few high-confidence candidates. Parallel discovery can
split independent owners. Delete obsolete seams and dead paths, move retained
regressions to their owner, and consolidate generic package/dependency contracts.
Prefer net-negative production LOC; never add replacement implementation tests
or turn uncertainty into cleanup.

## Validation and handoff

Follow [proof policy](../../openclaw-testing/SKILL.md#proof-policy); never edit a
checkout while its Vitest run is active. Run owner/sibling tests. For removed
source greps or plan assertions, exercise the owning executable/dry-run. Run
targeted format, `git diff --check`, and classify the changed gate with
`node scripts/check-changed.mjs --dry-run -- <changed-paths>` before running it.
Inspect `git diff --numstat` and get final autoreview.

Report causes, removed categories/seams, retained false positives, proof and
cost, production versus test/support LOC, PR state, and follow-ups. Commit,
push, or land only when authorized through the native maintainer workflow;
refresh from main and rediscover before another audit batch.
