# Chat behavior harness

`pnpm ios:behavior` measures what the chat transcript does on the simulator: whether rows jump, drift or rebuild while a reply streams, while the reader is scrolled up, when the keyboard moves and after a relaunch, and whether the transcript is drawn at all. It drives the real app against an isolated Gateway whose model is the scripted QA mock, so every run streams the same replies.

## Run it

1. Build the Debug app (`mobilebuildmcp simulator build`). The probe exists only in DEBUG builds.
2. One-time profile, Gateway stopped: `pnpm ios:behavior --setup` writes the `ios-ux` profile (loopback port 19061, token auth, model `mock-openai/gpt-5.6-luna`). It never touches `ios-sim` or `~/.openclaw`.
3. Start two long-running services, the mock first. Wait for it to print its URL before starting the Gateway: `run-node` rebuilds `dist` when it is stale (any new commit), and a Gateway started during that rebuild exits with "Installation replaced".

   ```sh
   OPENCLAW_BUILD_PRIVATE_QA=1 OPENCLAW_ENABLE_PRIVATE_QA_CLI=1 node scripts/run-node.mjs qa mock-openai --port 44180
   node openclaw.mjs --profile ios-ux gateway --bind loopback
   ```

4. `pnpm ios:behavior` pairs a fresh simulator through onboarding, runs every case three times, then deletes the simulator and prints a table. `--cases stream-turn,keyboard` and `--samples 1` narrow a run; `IOS_SIM=<udid>` reuses a simulator already paired with `ios-ux`.

   Typing through a UI driver sends hardware key events, after which iOS hides the software keyboard for good. The script therefore resets `HardwareKeyboardLastSeen` in the simulator's `com.apple.keyboard.preferences` while it is shut down, and cases enter prompts by pasting (`simctl pbcopy`, long-press, Paste). Never `type-text` in a case: one `type-text` left every keyboard-up case unable to show the keyboard while this harness was built ([#198293](https://github.com/openclaw/openclaw/pull/198293)).

**Done:** the summary table prints and the script exits 0: every `guard` case passes all gates in every sample, and every `bad` case still reproduces its bug in at least one sample. There is no majority vote: a jump in one sample is a jump users see. Probe logs, screenshots (`screens/`), a video per sample and `summary.json` land in `.artifacts/ios-behavior/<time>/`. A full run takes about an hour; narrow it with `--cases` while working, run all of it before landing an iOS transcript, composer or keyboard change.

## What it measures

The chat has two reading policies after a send (`ChatView.handleTimelineChange`): with the keyboard hidden it pins the sent message near the top and the reply grows below it; with the keyboard up it follows the live edge. Each has its own case.

| Case                                                                                                                          | Gates                                                                                                                                                                                | Reported                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stream-turn`: 300-delta reply sent with the keyboard hidden                                                                  | drawn transcript holds still on the recording (≤ 1 pt after the first second, including the live bubble → final row handoff), no teleport (one-frame move > 400 pt), no row remounts | probe row drift, send → own bubble, send → first text, body evaluations                                                                                                                                                |
| `stream-follow`: the same reply sent with the keyboard up                                                                     | reply followed while streaming (p95 ≤ 4 pt hidden below the composer), end in view after it finishes (≤ 4 pt), no row remounts                                                       | teleports and backward motion: in about one run in ten the transcript flashes to the top for ~80 ms as the final row replaces the live bubble; the reply's end dips ~40 pt for a frame as the working indicator leaves |
| `scrolled-up`: reader scrolls up while an 80 s reply streams                                                                  | visible rows drift ≤ 1 pt once the scroll settles, no remounts                                                                                                                       | content hidden below                                                                                                                                                                                                   |
| `keyboard`: keyboard up and down at the end                                                                                   | gap above the composer within 1 pt of the start, no teleport                                                                                                                         | keyboard lift, gaps                                                                                                                                                                                                    |
| `relaunch`: cold launch into a session with history, three launches per sample                                                | opens at the end                                                                                                                                                                     | launch → composer, launch → rows, shift after first rows, teleports (intermittent on `main`, so reported only)                                                                                                         |
| `switch-session`: six sidebar switches between two long agent chats and a short one                                           | transcript text on screen in every sample for 3 s after each switch                                                                                                                  | blank samples                                                                                                                                                                                                          |
| `blank-{up,down}-{short,long}-{plain,agent}`: keyboard up or down at send × new or long chat × plain or agent reply (8 cases) | transcript text on screen in every sample from composer focus until 3 s after the reply ends                                                                                         | blank samples                                                                                                                                                                                                          |

Every case also ends with a screen check (transcript text on screen at the end), so cases that gate on motion are judged on what is drawn too.

Gates are positions and counts; they come out the same on any Mac. Times are simulator wall-clock: compare them A/B against `main` on the same machine, never against a fixed budget. Frame pacing and hitches need a device and Instruments ([DEBUG.md](DEBUG.md)).

A `(setup)` gate failing means the case did not reach its state (keyboard not shown, reply too short to pass the fold, not scrolled away). Fix the setup before reading other gates.

Each case is a `guard` (every gate passes in every sample) or `bad` (reproduces an open bug: setup passes, another gate fails in at least one sample). Add a new bug as a `bad` case before fixing it; a fix that makes it pass all gates fails the run until the case is changed to `guard` in the same PR. An intermittent bug that does not reproduce reliably stays a reported metric, never a gate: a flaky gate gets retried and ignored.

## The screen oracle

A blank transcript went unnoticed for weeks ([#191478](https://github.com/openclaw/openclaw/issues/191478)): with the keyboard up in a long agent chat, a send left the transcript empty for 13–15 s on iPhones, while the progress card, run footer and composer stayed drawn. This harness missed it twice over: every case streamed plain mock markdown with no tool rows or progress card, and nothing looked at the screen. The probe's frames read blank while text was visible (a re-keyed row remounts), and the accessibility tree still listed the card and footer while no message was drawn.

So blank-transcript gates judge pixels. `scripts/ios-screen-text.swift` (Apple Vision, accurate level; the fast level misses text on gray bubbles) reads each screenshot; the harness counts recognized lines whose center is inside the `chat-transcript` frame, above the composer, and outside the progress card and run footer. Zero lines while the chat has history is a blank transcript; the run logs the screenshot. Checked on 24 labeled screenshots, including six frames from an iPhone recording of #191478: 24/24 right; on that recording it found the blank from 5.5 s to 20.5 s (5.3–20.6 s by eye). Sampling is about one screenshot per 0.4 s, and recognition about 0.2 s per screenshot.

Motion the reader sees is read from the recording too. `scripts/ios-screen-motion.swift` reads every native frame of a window of the case's video and compares it with a key frame. It cuts the transcript area into 40 pt strips. For every vertical shift of up to 400 pt (the probe's teleport threshold covers bigger jumps) it counts the changed strips that the shift brings back to the key frame's content, and takes the shift most strips agree on: at least two, and at least a third of the strips that changed. A strip that gained text fits no shift, and repeated wording fits one strip at a time, so neither counts as motion. The key frame is replaced every 250 ms and carries the offset measured at that moment, so streaming text barely changes it while slow drift still adds up. Moves smaller than 1 pt are below its resolution. A frame where most strips changed and no vertical shift explains them is reported as `drawnUnexplainedFrames`, not gated: on `main` the live bubble → final row handoff redraws the reply about 2 pt right and 1 pt down for a few frames. The area stops above the run footer and skips the jump-to-latest button's columns, because both appear or move by design. The window starts once the reply fills the screen: before that, the growing reply moves its own footer row down, which looks like a scroll. Its start is placed on the video by simctl's `Recording started` line, which the harness waits for before it starts the case. Checked on synthetic clips cut from a real recording: a 200 pt jump reads 200, a 350 pt jump reads 188 (fails the gate; few strips stay in the area to measure it exactly), a 30 pt bounce of 100 ms reads 30, three 1 pt steps read 3, one 1 pt blip of 50 ms reads 1, and a still clip reads 0. On 12 `stream-turn` recordings where the probe reported 10–79 pt, it reads 0 (the videos show no vertical motion). About 1.6 s per sample.

Rules that came out of #191478:

- A gate about what the reader sees reads the screen. Probe frames and accessibility explain a failure; they never decide that content is visible.
- Fixtures look like real chats. `UXAGENT steps=<n> chunks=<n> interval=<ms>` makes the mock run an agent turn: commentary plus a tool call per step (progress card updates alternating with `exec`), then the long markdown reply. Scenarios run in every keyboard × length × content combination, not one hand-picked mix.
- A new case is proven against a build that has the bug before it counts.

## Real transcripts

`--sessions <key>,<key>` uses existing chats wherever a case needs history, instead of seeding mock turns. To judge real conversations, copy a real profile's state to a scratch profile, point `--profile` and the paired simulator at it, and pass two long chats. Keep those copies and their screenshots out of git.

## How it works

- `ChatBehaviorProbe.swift` (OpenClawChatUI) runs only with `--openclaw-behavior-probe` in a DEBUG build. It writes `Library/Caches/behavior-probe.jsonl` in the app container: each frame where something moved (window-space top and bottom of every tagged row, the live bubble and the composer), mounts, scroll phases, bubble body evaluations, and `send` / `keyboard-show` / `keyboard-hide` marks. "End in view" compares row bottoms with the composer top, not scroll metrics: `LazyVStack` content height is an estimate.
- When a reply finishes, its final row replaces the live bubble; for one frame both exist and the outgoing bubble sits far below. The grader reads the final row as the bubble's continuation and ignores the outgoing one.
- Motion is read on edges the reader can see: a row's top when it is on screen before and after, else its bottom. A reply taller than the screen can change height above the fold without the visible text moving. A teleport is a move of both edges by more than 400 pt, so a jump counts even when the row lands from off screen. A row off screen in both frames does not count: the latest turn is laid out eagerly, so its rows stay mounted above the fold and shift when a height below them changes.
- Since the iOS transcript became a `List` (#192232), the probe reports cell layouts that never reach the screen while a reply grows: a row moves 5–60 pt, then returns or unmounts within about 250 ms, while the recording shows the reply still. So `stream-turn` gates on the recording, and probe drift is reported only. Before trusting a new probe motion number, check the per-sample video (`<case>-<n>.mp4`). Decode native frames with `-fps_mode passthrough`, because resampling to a fixed rate drops short frames.
- `scripts/lib/ios-behavior-grade.mts` reads the log. Frames inside a user drag or its deceleration are the reader's own motion and are skipped.
- The mock streams `UXSTREAM chunks=<n> interval=<ms>` as `n` markdown deltas `ms` apart, ending in `UX-STREAM-END` (`extensions/qa-lab/src/providers/mock-openai/mock-openai-ux-stream.ts`). Pacing applies to the SSE route the `ios-ux` profile uses; the mock's websocket route sends the deltas at once. The trigger is one all-caps word because the simulator keyboard autocorrects lowercase phrases.

## Add a case

Add an entry to `cases` in `scripts/ios-behavior.mts`: launch into a fresh session key, drive the UI with `mobilebuildmcp`, read the probe or the screen, return metrics and gates. Gate anything about visibility on `watchScreen` + `readScreens` + `screenGates`. Prove a new gate can fail: run it on a build that has the bug (or with the fix reverted) and keep the failing summary as evidence. Keep a copy of a pre-fix `.app` for that; `--app` runs any build.
