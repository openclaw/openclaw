# Wear OS behavior contract

The watch is a paired-phone companion. It never asks for, receives, or stores Gateway credentials, TLS pins, or device-signing identity.

- Given a reachable paired phone and connected Gateway, opening the watch app lists recent non-global sessions. Selecting one shows the latest bounded text transcript.
- Given long received chat text, Show more and Show less disclose the full received text locally. Show more above the latest eight messages reveals the rest of the already-loaded bounded transcript (at most twenty); it never requests older history. Disclosure preserves message identity and manual reading position and is not new incoming content. Phone, agent-owner, or session changes reset disclosure and picker state; the existing New action and incoming-content autofollow remain available. Selection controls expose their real selected state to accessibility services.
- Given multiple reachable phones, RPC responses and events are accepted only from the currently preferred phone. A preferred-phone change reloads canonical state before replaying live events.
- Given an unavailable phone or offline Gateway, the app shows one clear recovery state and a refresh action. It does not fall back to direct Gateway access.
- Given a paired phone that advertises agent and Gateway controls, the watch can select the phone's active agent and connect or disconnect its Gateway. Older phones omit those controls and continue serving the original companion surface.
- Given a selected session and advertised session model choices, the model picker reads and searches that session's catalog through the phone. A partial refresh keeps available choices visible with a warning. Changing phone, agent, session, or model clears the previous catalog warning. Older phones that advertise model controls without session catalog support show update guidance in the picker. Current phones disable model controls when the Gateway lacks session catalog support. Shipped Watches that omit the session field retain their phone-active-session behavior through the same Gateway catalog owner.
- Given a selected session, text input or Wear speech recognition sends one idempotent, non-delivering chat request through the phone. Within the same live Watch owner and unchanged phone/session, an explicit retry of an unresolved send reuses its request identity, including across Gateway reconnect or transient rediscovery of the same validated phone/session. Reconnect revokes stale input and send-UI authority without forgetting that identity. Only the latest send invocation may update retry state; its acknowledgment alone does not prove completion. A matching terminal event, canonical terminal history, definitive phone rejection before Gateway delivery, or conversation navigation ends that identity. A definitively rejected message permits corrected input without retaining the rejected key. No automatic retry or persistent outbox is created. An active run can be aborted.
- Given a selected session and microphone permission, Real-Time Talk streams bounded PCM audio over one temporary bidirectional Data Layer channel to that session on the selected phone. One watch owns the relay at a time. Stopping Talk closes local capture, playback, and audio streams before waiting for the phone to acknowledge Stop; Voice shows Stopping while that acknowledgment is pending. Clearing the Talk owner also closes its streams and requests channel closure before canceling its scope. Changing phones, losing the Gateway, or losing the channel closes capture and playback without exposing Gateway credentials to the watch.
- Given a failed microphone start or restart (including a native start that returns without recording) or audio-focus denial, the watch stops that audio attempt and shows a visible audio error rather than Listening. Manual and automatic reply speech share the same failure state and ignore callbacks from replaced utterances.
- Given denied microphone permission, Live explains the missing permission and offers Retry or Open Settings without hiding Dictate, Thread, or Type. Returning from Settings refreshes permission availability; granting permission never starts recording by itself. Starting Talk requires a fresh resumed-activity tap. Pausing invalidates pending capture intent, and a late startup result cannot restore it even after returning. Already-active calls retain their existing paused-but-visible behavior; stopping the activity stops local audio. Returning never restarts capture by itself.
- Given an accepted reply and a matching remote terminal event, the watch settles the pending reply even when history has no new assistant message. Errors remain visible through history refresh; a new reply or conversation context clears the prior outcome. Foreign identified terminals and ambiguous anonymous streams cannot settle a newer run.
- Given ordered chat events, the transcript shows the phone's bounded canonical stream projection, including replacements that shorten or clear it. Given a missing sequence or changed phone-process epoch, the app discards uncertain stream state and reloads canonical history. Events racing that snapshot replay only when they share its epoch and are newer than its response watermark, and stream text reconciles without duplication or a reload loop. A legacy phone without response watermarks lets the next event establish its live baseline.
- Given a final assistant message while the app is not visible and notifications are allowed, the watch shows one local-only notification with direct reply. Phone-process recreation rediscovers the reachable watch before delivery. If the preferred phone changes before a notification reply, recovery opens the app to reload the session instead of retrying the stale phone.
- Given a reply notification, both its open and recovery actions retain the originating phone and session. Cold and warm opens load that conversation even when another agent is selected on the phone. Navigation finishes the original Talk attempt before opening a different context. A changed phone produces a visible recovery error rather than opening or replying to an identically named conversation on the new phone.
- Given text, speech, or model-search input after navigation, only the captured conversation generation may act. Microphone-permission results update availability only and never start capture. Leaving and returning to the same session does not authorize an old result or let an old send completion settle a newer attempt. Qualified session keys retain their agent owner; no request infers ownership from later phone selection.
- Given Android 13 or newer without notification permission, Controls offers both an explicit request action and direct access to the watch's app-notification settings. Granting or revoking permission outside the app is reflected when the app resumes, and denying it leaves the rest of the companion usable.
- Given a theme or automatic-speech selection, the watch persists that local UI preference without sending it to the phone or Gateway.
- Given a connected paired phone that advertises Agent Pulse, the Pulse page pulls bounded aggregate background-task, selected-session swarm, and pending-approval state only while that page is visible and the app is resumed. Leaving the page, pausing, changing phone, agent, or session, or losing connectivity stops polling and suppresses stale Pulse state. The watch exposes no task text, identifiers, approval details or actions, credentials, or direct Gateway access.
- Given the OpenClaw Tile, tapping its mascot Talk action opens the watch app directly on Voice, while the secondary Open edge action starts on Chat. The tile uses the official Android app launcher artwork from the phone manifest's `@mipmap/ic_launcher_foreground` resource with the Core app's dark visual tokens. Neither launch starts microphone capture. Tile rendering performs no phone or network work and persists no cache.
