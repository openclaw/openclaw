# Concept page layout

A concept page answers: what does it mean, how does it work here, what is it
not, and what rules govern it? Explain the concept as it stands, not the history
of the discussions about it. Use these sections after State, in this order, and
only those the evidence supports. Follow the general rules in
[subject pages](profiles.md), including the default of no change.

- `## How it works`: the mechanism or practice as it operates now.
- `## Distinctions`: what it is easily confused with, and the difference.
- `## Decisions and policies`: adopted rules that govern it, with who decided
  and why. A proposal is not a policy.
- `## Examples`: one or two concrete cases.
- `## Open questions`: what is unresolved, with who owns it.

A concept page never uses project headings (Key decisions, Milestones, People,
Commitments and deadlines). A dated run of the practice (one release, one
incident) is an event claim, or its own project page when it qualifies; the
concept page states the rule it established.
