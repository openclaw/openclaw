## Conversations in the Control UI

Details brings your conversation context, pull requests, background work, automations and task progress together, leaving more room above the message box. Its collapsible sections make the workspace, branch, model, context usage and changes easier to inspect. On wide chat panes, Details opens automatically beside the conversation with its own scroll; narrower panes use an overlay you can open when needed. If you close it, your choice is respected.

In Appearance, you can turn off theme artwork or choose a private image for New Session, conversations or both, and adjust its visibility. Your first upload appears on New Session only until you change its placement.

You can move a nested conversation to the top level, Pinned or a custom group using its menu or by dragging it. Archive affects only the selected conversation and leaves its unarchived children available. **Archive session and children** shows the number of descendants and warns about active work before you confirm. It reports partial failures, and Undo covers only successfully archived conversations when their current state allows it.

To return to a conversation at a particular time, choose **Choose another time** in its session menu and enter a future local date and time. A successful choice is available as **Custom** in other session menus for up to one hour, while the time is still in the future.

A session's automation hovercard now shows attached jobs and their schedules, next runs and outcomes. Select a job, including a paused one, to inspect its instructions or open it in the automation editor.

## Speech and Talk

Control UI Read aloud and dictation now use your configured Gateway speech services, including local transcription providers. In split Talk mode, browser conversations use your current chat agent together with configured speech services. This mode does not support realtime voice switching or camera input; existing realtime Talk remains available when split mode is unset. Microphone access requires a secure browser context. See the [Control UI feature reference](/web/control-ui/feature-reference).

Talk voice and model choices now return from the last successful load while provider readiness refreshes, so they remain available during a slow or failed refresh. The first load may briefly wait, and starting Talk still checks current credentials and policy.

In Control UI Talk routed through the Gateway, a request that has already been accepted can finish and keep its answer in conversation history when the browser reports a Talk failure to a Gateway that supports this recovery. Stop still cancels the run. Older Gateways retain the previous cancellation behavior.

Authenticated Talk requests now use your ordinary permissions and approvals without an extra spoken confirmation, including after an upgrade. Actions requiring approval still wait for it, and saying “yes” in the conversation does not grant approval. See [Talk sessions](/nodes/talk/realtime-sessions).

## Conversations and workspaces

You can start a conversation in an existing folder on a compatible paired device, including a folder that is not a Git repository. Choose **Existing folder on device** in New Session. The device controls which folders are allowed, and the files stay there when the session ends. The session stays on that device, with no cloud or Auto dispatch, Gateway Files, or attachments. Files are not copied to the Gateway. See [session hosting](/nodes/session-hosting).

Session menus in the sidebar, Sessions page and chat header now offer moves for eligible session-owned worktrees and repository workspaces. When the session menu offers **Retry move** for a failed move, it uses the saved destination. A local turn finishes before moving; moving an active remote session interrupts the turn without replaying it. Leaving an offline device behind requires confirmation. See [sessions and the sidebar](/web/control-ui/sessions-and-sidebar).

Cloud projects can define supported setup and startup commands in a committed Dev Container file and reuse prepared dependencies. Projects without a recipe or executable setup script can also have common JavaScript lockfiles detected for dependency installation. This supports cloud project workers and selected lifecycle commands, not the full Dev Container specification.

Later eligible empty-workspace cloud sessions can start on a compatible ready worker once one is available. The first session provisions normally, capacity limits apply, and ready workers are running machines that incur provider charges.

Cloud setup and repository commands can use approved secrets bound to HTTPS destinations while keeping snapshots and prepared workers available. Bind secrets only to trusted services, which could return a credential in their response. This requires a supported Linux worker and Crabbox 0.77.0 or newer. If you use `setupEnv`, create destination-bound protected store entries and run `openclaw doctor --fix` before new provisioning. See [secret store and egress](/gateway/secrets/secret-store-and-egress).

Locally saved images, video and music generated by a sandboxed agent can now be copied into its requesting sandbox, including results that finish after the turn. On a successful copy, the returned sandbox file path lets the agent read, edit or reuse the result.
