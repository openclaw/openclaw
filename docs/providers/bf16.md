[bf16.ai](https://bf16.ai) serves uncensored open-weight models (with refusal
behavior edited out of the weights rather than papered over with system prompts)
through an OpenAI-compatible API. OpenClaw provides it as an official external
provider plugin with live `/v1/models` discovery, a starter model catalog, and
API-key authentication. OpenClaw's own local workspace, approval, and sandbox
policies remain the active safety boundary.

| Property        | Value                                          |
| --------------- | ---------------------------------------------- |
| Provider id     | `bf16`                                         |
| Package         | `@openclaw/bf16-provider`                      |
| Auth env var    | `BF16_API_KEY`                                 |
| Onboarding flag | `--auth-choice bf16-api-key`                   |
| Direct CLI flag | `--bf16-api-key <key>`                         |
| API             | OpenAI-compatible (`openai-completions`)       |
| Base URL        | `https://api.bf16.ai/v1`                       |
| Default model   | `bf16/deepseek/deepseek-v4.1-flash-uncensored` |

## Setup

Install the plugin:

```bash
openclaw plugins install @openclaw/bf16-provider
```

Installation applies to a running Gateway automatically; otherwise it takes
effect on the next startup. See
[Apply changes and inspect](/plugins/manage-plugins#apply-changes-and-inspect).

Run onboarding:

```bash
openclaw onboard --auth-choice bf16-api-key
```

For non-interactive setup:

```bash
openclaw onboard --non-interactive --accept-risk --skip-health \
  --mode local \
  --auth-choice bf16-api-key \
  --bf16-api-key "$BF16_API_KEY"
```

Or expose the key to the Gateway process:

```bash
export BF16_API_KEY="sk-bf16-v1-example-not-real"
```

Verify the provider:

```bash
openclaw models list --provider bf16
```

## Troubleshooting

- `401` or `403`: confirm `BF16_API_KEY` is valid and visible to the Gateway
  process, or run onboarding again.
- Missing provider: install `@openclaw/bf16-provider` and check
  `openclaw plugins list` before selecting a model.
- Managed Gateway cannot see the key: put it in `~/.openclaw/.env` or another
  trusted environment source loaded by the service. See
  [Environment variables](/help/environment).
